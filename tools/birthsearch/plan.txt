Build a complete, modern, responsive BDRIS Book Searcher Dashboard whose ONLY purpose is searching birth-registration records extracted from OCR-converted Google Docs/DOCX files stored in the data/ folder. Do not create an admin panel, login system, user management, manual record-entry interface, or unnecessary CRUD features. The application should automatically read/index the available book data from data/ and provide a professional Bangla-first search dashboard optimized for fast record lookup. Create a clean header with the title "BDRIS Book Searcher", a short subtitle explaining that users can search birth-registration book records, and small statistics showing Total Books, Total Records, and optionally Indexed Pages. The main area should contain a prominent search card with four primary fields: Date of Birth, Name, Father's Name, and Mother's Name. Each field must have clear Bangla labels, useful placeholders, and independent input support so the user can search using only one field or combine multiple fields. Date of Birth should support common formats such as DD/MM/YYYY, DD-MM-YYYY, Bangla digits and English digits. Name, Father's Name and Mother's Name searches must support Bangla text, partial matching, flexible spacing, common prefixes such as মোঃ/মো./মো, and common OCR variations. Normalize Bangla and English numerals, punctuation, whitespace, Unicode variations and common OCR mistakes before searching. Provide two search modes: Exact Match for highly precise searching and Flexible Match for OCR-tolerant partial/fuzzy searching. When multiple fields are entered, treat them as combined filters and prioritize records matching the highest number of fields. Do not require every field to be filled. Include a prominent Search button, Clear/Reset button, Enter-key search support, loading indicator, empty-search validation, and a friendly no-results message. Results should appear immediately below or beside the search area in a clean responsive layout. Each result should clearly display Name, Father's Name, Mother's Name, Date of Birth, Registration Number if available, Serial Number if available, Book Name/Number, Page Number, and the original source filename. Highlight the portions of the result that matched the user's search query. Display a confidence or match indicator when fuzzy/OCR matching is used, but do not expose confusing technical information to normal users. Provide a "View Source" or "Open Book Page" action that opens the corresponding original OCR book/document or source reference at the correct page/location whenever possible. If the source is a PDF or page image, provide a source preview where practical. Add pagination with configurable results per page, total result count, current result range, Previous/Next buttons and page numbers. Preserve the user's search criteria while navigating pages. Add sorting/relevance ranking so the strongest matches appear first, especially exact DOB + name + parent-name matches. The dashboard should be optimized for large datasets and should not scan every DOCX file on every search; create an indexing/search layer from the data/ folder and use an efficient database/search index such as MySQL with properly indexed columns, while preserving the original OCR text and source file/page information for verification. The system should automatically detect newly added book files in data/ and provide a lightweight indexing mechanism without requiring an admin panel. Design the UI in 100% Bangla by default, using a suitable Bangla font such as SolaimanLipi/Noto Sans Bengali, with clear typography, accessible contrast, rounded cards, subtle borders/shadows, responsive spacing, and a professional government-service-style appearance without copying the official BDRIS website. Desktop layout should use a wide search/results workspace, while mobile should stack the search fields and results vertically. Include keyboard-friendly navigation, proper labels, accessible buttons, responsive tables/cards, and fast loading. Add useful states including initial dashboard state, searching state, results state, no-results state, invalid-input state, source-not-found state and indexing/error state. The final dashboard flow should be extremely simple: open dashboard → enter Date of Birth and/or Name/Father/Mother → choose Exact or Flexible search → click Search → review ranked matching records → open the relevant book/page for verification. Keep the interface focused entirely on fast, accurate searching of the OCR-converted BDRIS books in data/.
